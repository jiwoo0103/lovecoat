# 검수 화면 디자인 기준 — 2026-11-03

2.6.1 UI에서 확인 대상 카드와 입력란의 색, 홈 카드, 제목 표시줄, 하단 활성 탭을 후속 변경했다. 2.6.2부터 홈 카드의 제목 띠는 테두리 안쪽 양끝까지 채우고, 카드 입력란의 선택 목록은 뒤 화면을 어둡게 하지 않는다. 최신 동작은 [구현 상태](../PROJECT_STATUS.md)를 참고한다. 아래는 2.6.0 디자인 기록이다.

상태: **2026-11-04 사용자 요청으로 채택한 디자인을 앱 QML 소스에 적용했다.** 공통 테마는 `coatdesk_v2/qml/Theme.qml`이며 홈·검수·설정·사진 확대·엑셀 저장창을 함께 전환한다. 상단의 배경 박스 없는 해·달 아이콘과 420ms 회전·축소 전환, 마지막 테마 저장을 구현했다. 최신 구현·검증 범위는 [UI 적용 기록](UI_IMPLEMENTATION_20261104.md)을 우선한다. 아래의 ‘미적용·추후 검증’ 문구는 당시 디자인 기록이며 현재 구현 상태는 적용 기록과 구분한다. 모델·실사용 DB·설치본·커밋·푸시는 이번 UI 작업에서 변경하지 않았다.

- 채택 이미지: [review-light-soft-pending-card-v5.png](../.local/ui-design-20261103/review-light-soft-pending-card-v5.png).
- 이미지 SHA-256: `1d60a49fcdf5abecd108de0703a64a26943af241a11cea23df88743e789d5bd5`.
- 상단: 분석은 파랑, 확인 필요는 노랑, 엑셀 저장은 초록이며 각각 아이콘과 글자를 함께 사용한다. 배치·분류는 중립색 배경과 아이콘을 유지하고 배치 버튼의 격자 수 표시는 숨긴다.
- 확인 필요 버튼은 현재 작업에 확인 대상이 있을 때만 표시한다. 확인이 필요한 옷 카드는 아주 연한 노랑, 해당 필드의 값·경고·사유는 차분한 붉은색으로 표시한다. 사진과 정상 필드는 유지한다.

- 채택 범위는 **v5 검수 화면의 구조·공통 규칙과 후속 v6 라이트·다크의 색상 방향**이다. 기본 상태의 HEX 기준은 별도 JSON에 저장했다. 호버/눌림/포커스/비활성/오류·고밀도 배치·글꼴 등 아래 미확정/미검증 사항까지 완료된 것으로 해석하지 않는다.
- 이 채택 기록은 실제 앱에 적용했다는 뜻이 아니다. 사용자 데이터·AI 모델·입력/확인·엑셀 저장 로직은 이번 기록에서 변경하지 않았다.

## 최신 디자인 방향

- 노션처럼 차분한 무채색 바탕, 절제된 선과 여백, 부드러운 모서리. 기존 PySide6/QML을 유지한다.
- **라이트·다크 두 모드를 지원하는 방향**이다. 이전의 단일 라이트 모드 결정과 Fluent 탭을 주된 외관 참고로 삼은 계획은 이 기록으로 대체한다. 두 모드의 v6 전체 화면 시안과 기본 색상표를 기록했고 실제 앱에서는 같은 구조·치수와 상태 대비를 후속 검증한다.
- 무채색 바탕을 유지하면서 상단의 역할을 구분한다. **분석은 파란 채움·흰 글자와 아이콘, 확인 필요는 노란 채움·진한 글자와 경고 아이콘, 엑셀 저장은 초록 채움·흰 글자와 파일 아이콘**으로 표시한다. 배치·분류·검색은 중립색을 유지한다. **확인이 필요한 옷 카드만 배경을 아주 옅은 노랑으로 바꾸고, 확인이 필요한 필드의 값과 경고 표시·사유는 차분한 붉은색으로 표시한다.** 정상·완료를 알리는 상시 초록 배지는 두지 않고 중립색 체크·문구를 사용한다. 오류·삭제 안내는 해당 사유·문구와 함께 구별한다.
- 각 테마의 기본 상태 HEX 기준은 [ui-colors-v6.json](design/ui-colors-v6.json)에 저장한다. 런타임은 JSON을 직접 읽지 않고 같은 기준값을 `Theme.qml`의 역할별 색으로 정의한다. 호버·눌림·포커스·비활성·오류·활성 탭도 공통 테마로 구현했으며 생성 이미지 픽셀 실측값과 구분한다.
- 사진의 원래 색과 밝기는 테마와 무관하게 유지한다.

## 상단과 하단 구성

```text
작업 이름 · 날짜 · 수량                  자동 저장됨   [파일 아이콘 + 엑셀로 저장: 초록] [작업 메뉴]
[분석 아이콘 + 분석: 파랑]   [경고 아이콘 + 확인 필요 N: 노랑, N>0일 때만]   [격자 아이콘 + 배치 ▾]   [옷 번호 검색]   [필터 아이콘 + 분류 ▾]

                        사진 + 입력값 2×2 검수 화면

←   현재 / 전체 페이지   →
홈   활성 작업 ×   다른 작업 ×   +
```

- `분석`, `확인 필요 N`, `배치`, `분류`, `엑셀로 저장`은 **아이콘 + 글자**로 표시한다. 분석은 이전 시안의 막대형 분석 아이콘, 확인 필요는 경고 삼각형, 배치는 격자, 분류는 필터, 엑셀 저장은 시트/파일 아이콘을 사용한다. 아이콘 기본 크기 16px·선 1.5px·글자와 간격 8px를 유지한다. 이 결정은 v1/v2의 상단 장식 아이콘 제거와 v3의 글자만 있는 엑셀 저장 방침을 대체한다.
- `확인 필요`는 **현재 작업의 확인 대상이 1개 이상일 때만** 경고 아이콘·문구·개수를 함께 표시한다. 0개면 버튼 자체를 숨기고 `확인 필요 0`이나 비활성 버튼을 남기지 않는다. 현재 페이지에 대상이 없어도 작업에 확인 대상이 남아 있으면 표시한다. 이 표시 조건이 분석·검수·저장 조건을 바꾸거나 검수를 자동 완료시키는 것은 아니다.
- `분석`은 파랑, `확인 필요 N`(대상이 있을 때)은 노랑, `엑셀로 저장`은 초록으로 역할을 강조하고, `배치`·`분류`는 옅은 중립색 배경으로 조작 영역을 드러낸다. 상단 버튼은 높이 36px·라운드 6px·기본 테두리 없음으로 통일한다. 호버·눌림에서는 각 역할의 배경 단계를 조절하면서 글자·아이콘 대비를 유지한다. 특히 노란 버튼에 흰 글자를 쓰지 않는다. 실제 테마별 색상값·호버·눌림은 구현 검증 대상이다.
- 확인 필요 버튼의 출현·숨김은 분석 오른쪽의 가변 여백에서 처리하고, 오른쪽 배치·검색·분류 그룹과 카드 입력 위치를 이동시키지 않는다. 현재 두 이미지는 정적인 상태 예시이며 실제 전환 동작을 검증한 것은 아니다.
- `배치` 옆의 현재 격자 수 `2×2` 등은 상단에서 표시하지 않는다. 실제 1~4행·1~4열 선택과 현재 값 표시는 배치 메뉴 안에 유지한다.
- `배치`·`분류`의 펼침 화살표는 유지한다. 검색 돋보기, 저장 상태 체크, 작업 메뉴, 홈, 탭 닫기, 추가, 페이지 화살표, 입력값의 펼침 화살표, 실제 확인 대상의 경고 표시는 기능을 설명하는 표시로 유지한다.
- `엑셀로 저장`을 작업 제목 줄 오른쪽에 배치하고 주요 채움 버튼으로 강조한다. 기존 저장 창·미리보기·저장 조건·검증 절차를 유지한다.
- `분석`은 실행 중 `분석 중단`으로 표시하고 바로 접근할 수 있게 한다. 배치·번호 검색·분류·확인 필요 필터를 유지한다.
- 상단 입력창 ON/OFF 토글은 제거하고 기본 검수 화면에서 입력값을 계속 표시한다. 사진 전용 보기의 메뉴 접근 위치는 구현 전에 정리할 사항이며, 토글 제거만으로 사진 기능 전체 삭제를 의미하지 않는다.
- 옷 다중 선택의 체크박스·선택 테두리·선택 개수·선택/해제·일괄 기능은 제거하는 기존 요구를 유지한다. 입력값 선택·작업 탭 활성 상태·현재 옷 포커스·개별 편집·실행 취소는 유지한다.
- 자동 저장 안내는 상단 한 곳만 둔다. 하단에 같은 의미의 안내를 반복하지 않는다.
- 하단은 홈·열린 작업 탭·닫기·추가를 유지한다. 탭 닫기는 작업 기록 삭제와 구분한다.

## 크기·선·라운드

같은 역할은 같은 규격을 쓰되, 요소의 크기와 역할에 따라 제한된 단계로 나눈다. 모든 요소에 같은 라운드나 같은 외곽선을 강제하지 않는다.

| 대상 | 기본 크기 | 라운드 | 평상시 선 |
|---|---|---|---|
| 상단 버튼·검색창·드롭다운 조작 영역 | 높이 36px | 6px | 기본 선 없음; 분석 파랑·확인 필요 노랑·엑셀 저장 초록; 배치·분류·검색은 중립색 바탕 |
| 카드 내 입력값 행 | 높이 36px | 6px | 없음; 항목명·값·화살표로 표현 |
| 확인·빠른 입력 등 작은 버튼 | 높이 32px | 6px | 문맥에 따라 없음 또는 1px |
| 아이콘 전용 조작 영역·탭 닫기 | 32×32px | 6px | 평상시 없음 |
| 기능 아이콘 | 기본 16×16px | 형태에 따름 | 아이콘 선 1.5px |
| 검수 카드·홈 작업 카드 | 배치에 따라 결정 | 10px | 기본 중립색 1px; 확인 대상 카드는 얇고 옅은 따뜻한 경계와 연노랑 배경 |
| 사진 영역 | 비율 유지, 카드에 맞춤 | 6px | 별도 외곽선 없음 |
| 드롭다운 메뉴·팝업·대화상자 | 내용과 화면에 맞춤 | 12px | 중립색 1px |
| 작은 상태 배지(필요한 경우) | 높이 24px | 4px | 기본 없음; 카드에 중복 배지를 상시 추가하지 않음 |
| 작업 탭 | 높이 36px, 바 기본 높이 44px | 6px | 개별 외곽선 없음; 활성 표시선 2px |
| 키보드 포커스 | 요소 크기 유지 | 대상 형태에 맞춤 | 2px 포커스 표시 |
| 화면 구분선·필요한 일반 외곽선 | 해당 영역 크기 | 해당 없음 | 기본 1px |

- 버튼의 기본 좌우 내부 여백은 각각 12px. 글자 길이에 맞춰 너비를 잡고 대화상자의 나란한 확인·취소 버튼은 너비를 맞춘다.
- 평상시 테두리가 없는 입력 행도 조작 영역과 키보드 접근성을 유지한다. 호버·포커스에서는 배경 또는 테두리로 조작 대상을 표시한다.
- 호버는 선 두께를 바꾸지 않고 배경·선 색으로 표현한다. 포커스 선으로 레이아웃이나 텍스트가 밀리지 않게 한다.
- 카드 내부에는 입력값마다 작은 상자를 만들거나 행 구분선을 반복하지 않는다. 입력 대화상자처럼 경계가 필요한 필드는 1px 선을 사용할 수 있다.
- 상단 버튼의 기본 배경 추가를 카드의 모든 입력 행으로 확대하지 않는다. 카드 입력값은 기존의 가벼운 항목명·값 표현을 유지한다.
- 상단·하단 바처럼 화면 가장자리에 붙는 면 전체를 별도 둥근 상자로 만들지 않는다. 네이티브 창 테두리는 운영체제 표현을 따른다.

## 간격과 정렬

| 위치 | 기준 |
|---|---|
| 화면 바깥 여백 | 16px |
| 카드 사이 | 12px |
| 카드 내부 여백·사진과 입력 영역 사이 | 16px |
| 항목 이름과 입력창을 위아래로 배치할 때 | 4px |
| 같은 그룹 안 조작 요소·아이콘과 글자 사이 | 8px |
| 별도 입력 항목 그룹 사이 | 12px |
| 상단의 서로 다른 도구 그룹 사이 | 24px |
| 대화상자 내부 여백 | 24px |

- 카드 오른쪽은 `옷 분류 / 사이즈 / 성별 / 연령` 네 행의 항목명·값을 같은 열에 정렬한다. 값은 바로 편집할 수 있고 별도 편집 모드 진입을 요구하지 않는다.
- 네 카드의 사진·속성 행 위치를 동일하게 맞춘다. 하단 확인 안내·확인 버튼 영역은 같은 높이를 확보해 필요한 카드만 행이 밀리지 않게 한다.
- 기본은 사진과 입력을 함께 보는 2×2 시안이다. 기존 1×1~4×4 배치·창 크기·Windows 배율에서 실제 읽기와 조작 가능 여부는 별도 검증한다. 이 표가 고밀도 화면의 검증 완료를 의미하지 않는다.

## 글자·상태·효과

| 역할 | 기본 글자 크기·굵기 |
|---|---|
| 작업 제목 | 20px, 중간 이상 굵기 |
| 카드 번호 | 15px, 중간 굵기 |
| 버튼·입력값 | 14px, 보통~중간 굵기 |
| 항목 이름·날짜·수량·보조 설명 | 12px, 보통 굵기 |

- 시선은 사진 → 입력값 → 확인 대상 순서로 유도한다. 모든 입력값·라벨을 굵게 표시하지 않는다. 글꼴 패밀리는 아직 확정하지 않았다.
- 확인 대상 옷은 **아주 옅고 채도가 낮은 노란 카드 배경**으로 표시한다. 카드 안 확인 대상 필드의 값·경고 아이콘·짧은 사유는 **채도가 낮은 진한 붉은색**으로 표시한다. 해당 옷의 다른 정상 값·항목명·번호·확인 동작은 기본 중립색을 유지한다. 예시는 #3443의 옷 분류만 붉게 표시하며 사이즈·성별·연령은 바꾸지 않는다. 이 기준은 앞선 황토색 값만 사용하고 카드 전체는 흰색으로 두는 시안을 대체한다.
- 밝고 쨍한 노랑·빨강, 카드 전체의 진한 색 채움, 두꺼운 붉은 테두리, 사진 위 색상 오버레이는 쓰지 않는다. 사진의 색과 밝기는 그대로 보존하고 연노랑은 카드 배경에만 적용한다. 정상 카드는 일반 배경을 유지하고 확인 대상이 해제되면 기본 카드·입력값 표현으로 돌아간다.
- 정상 카드에 완료 배지를 반복하거나 값 아래 사유와 카드 상단 경고를 중복하지 않는다. 입력·확인 로직은 기존 요구를 유지하며 이번 시안의 색 변경으로 확인을 자동 처리하지 않는다. 다크 모드의 대응 색상은 아직 별도 검증하지 않았다.
- 오류·저장 실패·필수 확인 등 중요한 안내를 단순히 숨기거나 의미를 색만으로 전달하지 않는다.
- 일반 카드에 강한 그림자를 쓰지 않는다. 팝업·대화상자만 필요한 만큼 은은한 그림자를 사용한다.
- 호버·눌림 색 전환은 120~160ms를 기본으로 한다. 입력 조작과 키보드 탐색을 지연시키지 않는다.
- 라이트·다크에서 구조·치수·라운드는 동일하게 유지하고 각 테마의 글자·배경·경계 대비는 별도로 정한다. 정상·호버·눌림·포커스·현재 값·비활성·오류·확인 필요와 열린 드롭다운을 모두 확인한다.

## 구현 전 남은 사항과 확인 범위

- 기본 상태 팔레트는 별도 저장했으며, 호버·눌림·포커스·비활성·오류·활성 탭 표시의 세부 색과 실제 앱 검증은 남아 있다. 글꼴, 테마 설정 위치·저장·초기값, 사진 전용 보기 접근 위치도 아직 구현 상세가 확정되지 않았다.
- 확인 필요 필터가 활성화된 채 마지막 확인 대상이 없어지는 경우에도 필터를 해제할 경로가 필요하다. 버튼 숨김 이후 빈 결과 영역의 전체 보기 등 구체적인 해제 동작은 구현 전에 정한다.
- 기본 크기 규격을 공유하는 QML 테마/공통 컴포넌트로 관리하는 방향이며 이번 기록에서 코드나 의존성을 추가하지 않았다.
- 이번 확인: 생성 이미지 육안 검토, 기록 파일·로컬 이미지 경로 확인, 문서 diff 검사. 실제 픽셀 실측·QML 실행·상태 전환·두 테마 대비·고밀도 배치 검증은 미실행이다.
- 모델·인식 기준·입력 데이터·분석 결과·엑셀 계약은 이 디자인 기록의 변경 대상이 아니다.
