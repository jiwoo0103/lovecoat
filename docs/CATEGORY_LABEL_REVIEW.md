- 2764번만 대화에서 사용자 확정. 나머지 114벌은 Codex의 육안 판독 초안입니다.
- 카테고리 학습 모델·수치 점수는 사용하지 않았으며 `model_score`는 `null`입니다. 모델 학습·대량 추론을 수행하지 않았습니다.

10월 27일에는 확정 라벨만 사용한 첫 카테고리 학습 실험을 별도 수행했습니다. 기존 육안 초안의 점수를 채워 넣거나 사용자 라벨을 덮어쓰지 않았습니다. 108벌·3분할 평가 106/108 일치와 보류 정책·모델의 한계는 [첫 학습 실험](CATEGORY_FIRST_MODEL.md)에 기록했습니다.

첫 실험 후 사용자의 명시적 승인으로 1181을 자켓, 1851을 코트로 수정해 기존 검수 화면에 확정 저장했습니다. 수정 전·후 파일과 변경 이력은 `model-results/20261026-category-label-review/label-correction-20261027-01/`에 보존했습니다. 현재 학습 라벨 스냅샷은 그 안의 `review-corrected.json`이며, 두 변경 외 나머지 113벌과 기존 모델·평가 기록은 그대로입니다. 이후 이 수정 라벨을 반영한 108벌 재학습을 별도 수행했습니다.

추가 검증 후보 30벌은 `model-results/20261026-category-label-review/validation-review-20261027-02/검수보기.html`에 있습니다. 기존 검수 115벌·카테고리 학습과 코드·그룹·사진 해시가 겹치지 않도록 선택했고, 전부 사용자 미확정 초안으로 생성했습니다. 자켓 11·코트 11·조끼 6·기타 보류 2, 성인 20·아동 10입니다. 사용자 확인 전에는 정답으로 간주하거나 학습·성능 계산에 넣지 않습니다. 모델 예측을 쓰지 않은 육안 초안이며 검수 화면에 모델 점수도 표시하지 않습니다.

사용자가 30벌 모두 확정한 CSV를 받아 재학습 모델로 별도 평가했습니다. 최종 확정 분류는 자켓 12·코트 12·조끼 6이며 결과는 26/30 일치(86.7%), 임시 95점 기준 통과 19벌 전부 일치·11벌 확인 필요입니다. 조끼 네 건을 자켓으로 오분류했습니다. 원본 검수 초안과 사용자 CSV를 덮어쓰지 않았고 결과·사진은 `validation-result-20261027-02/결과보기.html`에 별도 보존했습니다.

생성기는 각 묶음의 제목·기준 요약·`review_context`·`purpose`를 사용하며 최초 확정 수를 자료에서 계산합니다. 기존 2764번 기준 문구를 새 묶음의 확정 사실로 표시하지 않습니다. 신규 검수 메모는 입력 시 저장하고 JSON 내보내기에도 보존합니다. 기존 생성 HTML이나 브라우저 수정 상태는 자동으로 변경하지 않습니다. 집중 테스트 10개·Ruff, 새 묶음 필터·확대·별도 QA의 수정/확정/메모/새로고침 복원·JSON 내보내기를 확인했습니다.

분류별 보기, 성인/아동, 미확정/확인 완료/경계·사진 문제, 번호 검색, 사진 확대를 지원합니다.
각 사진의 분류를 수정하고 ‘분류 확정’을 누를 수 있습니다. 변경 시 기존 확정을 해제합니다.
수정은 해당 브라우저에 저장되며 JSON 내보내기/불러오기와 CSV 저장을 지원합니다.
정적 `labels-draft.json/csv`와 원본 사진을 브라우저에서 덮어쓰지 않습니다.

## 생성과 연결 규칙

생성 도구: `scripts/category_review.py`, 화면: `scripts/category_review_template.html`.
집중 테스트: `tests/test_category_review.py`.

입력은 기존 사진 목록의 `rows`와 별도 육안 판독 `entries`입니다. 이번 입력은 다음 로컬 경로입니다.

- `.local/ab-work-20261024-r3/manifest.json`: 사진 코드·경로·SHA-256·기존 중복 그룹 등.
- `.local/category-label-work-20261026-01/annotations.json`: 새 판독 초안·기준·보류 이유. 기존 성별·사이즈 라벨을 수정하지 않습니다.

```powershell
.\.venv\Scripts\python.exe -B -m scripts.category_review --manifest .local/ab-work-20261024-r3/manifest.json --annotations .local/category-label-work-20261026-01/annotations.json --output <존재하지 않는 새 결과폴더>
```

출력 JSON의 스키마는 `category-review-v1`입니다.

- `code`는 앞자리 0을 보존한 문자열, `folder_id`는 `0_2764` 형태입니다.
- `draft_category`는 최초 판독 분류이며 보류는 `null`; `display_category`는 화면 표시값입니다.
- `candidate_category`, `reason`, `hold_reason`은 보류 전 후보와 판독 근거입니다.
- `review_status=confirmed`인 경우에만 `training_label`이 채워집니다. 표시값 기타를 그대로 학습 정답으로 취급하지 않습니다.
- `source_sha256`과 기존 `source_group`, `previous_task_role`을 보존합니다. 이전 작업의 분할을 새 카테고리 학습 분할로 자동 확정하지 않습니다.
- 내보낸 검수 결과는 `dataset_id`와 `edits`를 포함합니다. 다른 묶음·알 수 없는 코드·지원하지 않는 분류는 변경 적용 전에 거부합니다.
- 별도 실험용 `scripts/category_first_model.py prepare`는 브라우저 JSON과 최초 묶음을 대조하고, 확정 상태·원본 해시·그룹·분포를 검사해 확정 라벨만 학습 대상으로 준비합니다. 기존 라벨 파일이나 앱 작업공간에 병합하는 도구는 아닙니다.

## 확인한 범위와 통합 주의

- 집중 테스트 9개 및 해당 Python 파일 Ruff 통과. 입력 검증·원본/기존 메타데이터 보존·결과 덮어쓰기 방지·보류/정답 분리·HTML 삽입 및 CSV 수식 방지를 검사했습니다.
- 선택한 원본 115장의 SHA-256과 기존 자료 목록 해시 불변 확인.
- 브라우저에서 분류별 보기, 아동 필터, 확대, 수정·확정·재실행 복원, JSON 저장·불러오기, 잘못된 파일의 원자적 거부를 확인했습니다.
- 수정·확정 시험은 다른 `dataset_id`의 `qa/검수테스트.html`에서 수행했습니다. QA 결과를 정답·학습 자료로 사용하지 않습니다.
- 실제 검수 화면은 2764번만 확정된 초기 상태로 열어 두었습니다. 최종 화면은 `검수화면.png`, 기계 판독 검증 기록은 `verification.json`, `browser-checks.json`에 있습니다.
- CSV는 생성/내용 검사를 수행했으며 Excel 앱에서 직접 열어보지는 않았습니다. 사용자 실제 검수·분류 정확도·다른 PC는 미검증입니다.
- `coatdesk_v2` UI·저장 계약·Google Sheets·기존 모델·학습 경로·빌드 설정은 변경하지 않았습니다. 앱 연결은 별도 작업입니다.
- 전체 테스트·빌드, 패키지 설치, 커밋·푸시·배포·외부 서비스 쓰기는 수행하지 않았습니다.
