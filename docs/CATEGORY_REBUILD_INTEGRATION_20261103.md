# 카테고리 재구축과 앱 통합 역할 분담

기준: 2026-11-03, Asia/Seoul. 최신 사용자 요청을 기록한다. 아직 학습·통합·새 설치파일 생성이 완료된 상태는 아니다.

## 최신 요청

- 카테고리는 기존 카테고리 체크포인트를 이어서 학습하지 않고, 일관된 데이터 라벨을 준비해 새 실험으로 다시 학습한다.
- 사용자가 **직접 대화할 별도 채팅으로 분리**를 선택했다. 같은 로컬 프로젝트에 **옷 카테고리 모델 재구축 · 라벨 통일** 채팅을 생성하고 기존 `category_rebuild` 서브에이전트의 읽기 전용 조사 결과와 질문을 전달했다. 별도 채팅 ID는 `01a1a1a1-e336-76d3-87bd-c7e0299904fe`, 호스트는 `local`이다. 학습·라벨 대화는 해당 채팅에서 진행하고 기존 일반 서브에이전트를 중복 실행하지 않는다.
- 메인 담당은 새 카테고리 모델과 기존에 새로 학습한 판넬·성별/연령·사이즈 세 모델을 통합하고, 채택한 v5 UI 요구사항을 적용·검증한 뒤 로컬 Windows 설치파일을 만든다.
- 따라서 이전 문서의 **카테고리 라벨링 보류**와 **설치파일을 만들지 않음**은 이번 요청 범위에서 해제한다. 커밋·푸시·공개 배포·외부 업로드·실사용 PC 설치까지 요청한 것은 아니다.

|---|---|---|

초기 카테고리 조사는 읽기 전용으로 완료했고 파일 수정·학습은 하지 않았다. 별도 채팅에는 신규 `scripts/category_rebuild_*.py`, `tests/test_category_rebuild_*.py`, 별도 카테고리 문서와 새 실험 경로를 담당하는 경계를 전달했다. 실제 파일 추가 전 기존 작업과 충돌 여부를 확인한다. 두 담당이 동일 파일을 동시에 수정하지 않는다.

## 데이터와 학습의 선행 확인

- `docs/NEXT_SESSION_HANDOFF_20261103.md`와 `docs/CATEGORY_LABEL_REVIEW.md`에서 자료·사용자 입력·라벨 기준의 기존 기록을 확인하고 실제 파일과 대조한다.
- 기존 브라우저에서 추가했을 수 있는 사용자 라벨을 회수·보존한다. 보존한 AI 초안을 사람 확정 정답으로 처리하거나 새 작업으로 덮어쓰지 않는다.
- 4120 기준·소매/기장·긴 민소매 예외 등 기존 기준과 사용자 최신 의도를 확인한다. 불명확한 경계는 임의의 정답으로 확정하지 않는다.
- “처음부터”는 최소한 기존 카테고리 모델 재개 학습을 하지 않는다는 뜻이다. 범용 사전학습 백본까지 금지하는 완전 무작위 초기화인지 등 학습 설계에 영향을 주는 사항은 실제 학습 전에 사용자와 확인한다.
- 기존 승인 조명 증강과 원본+고정 8변형의 9조건 평가를 기본으로 검토한다. 중복 옷 그룹의 분할 누수, 개발/최종 분리와 평가 정답의 독립성을 유지한다.

## 실제 구현에서 확인한 통합 주의사항

- `coatdesk_v2/ai_runtime.py`는 현재 세 모델을 순수 state dict로 읽고, 클래스 순서는 `coatdesk_ab.data`의 기존 값을 사용한다.
- `model-results/20261102-robust-four-models/manifest.json`의 새 세 후보는 `state_dict`를 포함한 래퍼이며 사이즈는 18출력이다. 새 사이즈 순서는 `70,80,90,100,110,120,130,140,150,160,170,XS,S,M,L,XL,2XL,3XL`이다.
- 가중치 이름만 바꿔 복사하지 않고 모델 구조·클래스 순서·전처리·아동 사이즈 대응·manifest 검증·분석 캐시 계약을 함께 검증해야 한다. 보존 실험 후보 자체는 변경하지 않는다.
- 현행 카테고리 런타임은 320 입력의 `efficientnet_b0_sleeve_length_2x2`, 소매 2개+기장 2개 확률, 안내판 마스킹과 letterbox를 사용한다. 이것은 현행 계약 기록이며 새 모델의 구조를 이미 확정했다는 뜻은 아니다.

카테고리 담당의 최종 인계에는 체크포인트와 SHA-256, 구조·출력/클래스 순서, 전처리·입력 크기, 소매/기장 또는 새 출력의 의미, 검수 예외·지원 범위, 평가 결과·재현 방법·CPU 실행 지침이 필요하다.

## UI와 최종 산출물

- [채택된 디자인 기준서](UI_DESIGN_SPEC_20261103.md)의 v5 시안·치수·동작 조건을 따른다. 분석 파랑, 확인 필요 노랑(대상 있을 때만), 엑셀 저장 초록+아이콘, 확인 대상 카드 연노랑·해당 입력값 차분한 붉은색을 유지한다.
- 라이트·다크 지원, 입력창 토글 제거, 옷 다중 선택과 연결 기능 제거, 카테고리 필터, 상단 엑셀 저장, 하단 작업 탭 요구사항을 통합 범위에 포함한다.
- 다크 팔레트·상태 대비·고밀도 배치 등 실제 검증되지 않은 사항은 구현 과정에서 검증한다. 중요한 미확정 동작은 질문하며, 시안을 근거로 데이터 처리 방식을 바꾸지 않는다.
- 새 카테고리 모델 준비 전에는 최종 네 모델 통합·최종 설치파일 검증이 완료됐다고 보고하지 않는다. 그동안 새 세 모델과 UI 등 독립적인 준비는 진행할 수 있다.
- 기존 저장·수동 수정/확인·ROI·실행 취소·페이지 탐색·입력 보존·엑셀 저장을 검증하고 기존 빌드를 보존하는 새 경로로 설치파일을 만든다.

이번 기록에서 모델 교체·학습 실행·앱 코드 적용·설치파일 생성·사용자 DB 변경·커밋·푸시는 수행하지 않았다.
