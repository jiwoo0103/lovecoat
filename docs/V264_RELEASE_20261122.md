# 외투작업실 2.6.4 사이즈 모델 교체

사용자가 선택한 첫 20종 사이즈 모델만 2.6.3 앱에 통합한다. 아동 숫자 `60`과 성인 문자 `2XS`를 추가하고 기존 17·18종 모델도 로더에서 계속 지원한다. 출력 순서는 검증하며, 아동 `60/70 → 2XS`를 비롯한 기존 변환표를 유지한다.

선택 가중치는 `model-results/20261122-size-retrain/size20.pt`, SHA-256은 `5f6ccbb292cb9ade5f7b4dd8c184aa12533f474894a15a2563eff9aa48393290`이다. 판넬·성별/연령·카테고리 모델과 정책·변환표는 실제 배포 2.6.3 자산에서 복사하고 파일 해시를 대조한다. 새로운 카테고리 후보와 희소 사이즈 추가 학습 후보는 사용하지 않는다. UI, DB 형식, 수동 입력 보호, 확인 기준, 엑셀 저장, 설치 방식은 변경하지 않는다.

검증 입력은 학습에 사용하지 않은 기존 최종 실사 중 사이즈별 120장, 희소 실사 추가 확인용 10장, 성인 문자 `2XS` 합성 10장이다. 실사 130장은 성인·유아동 각 65장이며 자켓 81·코트 31·조끼 13·기타 5장이다. 희소 실사 추가 확인에는 학습 사진이 포함된다. 새 촬영일의 독립 평가가 아니며, 성인 문자 `2XS` 실사와 `170`의 독립 평가 사진은 없다. 합성 결과를 실사 정확도로 해석하지 않는다.

## 기존 모델과 동일 사진 비교

실제 앱의 `RecognitionEngine.analyze`를 CPU 4스레드로 실행했다. 양쪽 모델을 3장씩 준비 실행하고 고정 난수로 사진별 모델 실행 순서를 섞었다. 측정 중 테스트·빌드는 실행하지 않았다. 이미지 읽기·판넬 탐지·성별/연령·사이즈·기존 카테고리 추론을 포함하며 UI 갱신·DB 저장은 제외한 시간이다. 최초 초기화 시간은 파일 캐시 영향이 커 비교 수치로 사용하지 않는다.

| 사진 묶음 | 기존 2.6.3 사이즈 정답 | 신규 2.6.4 사이즈 정답 |
|---|---:|---:|
| 학습 제외 실사 120장 | 119/120 (99.17%) | 120/120 (100%) |
| 희소 실사 추가 확인 10장 (학습 사진 포함) | 7/10 | 10/10 |
| 성인 문자 2XS 합성 10장 | 0/10 | 10/10 |

실사 130장을 합친 수치는 126/130 → 130/130이며 독립 평가 정답률로 인용하지 않는다. 실제 `60` 사진 4장은 0/4 → 4/4, `70` 사진 7장은 양쪽 모두 7/7이다. 읽은 원문과 앱 입력용 변환 사이즈의 정답 수는 위 표에서 같다. 실제 `60` 중 독립 최종 사진은 1장뿐이다.

실사 130장 평균은 **0.5441 → 0.5458초/장**, 중앙값은 양쪽 약 0.5398초, 95백분위는 0.5802 → 0.5878초다. 계산상 약 110장/분이며 이 PC의 준비 실행 후 CPU 추론 기준이다. 약 0.3%의 시간 차이로 처리 속도는 비슷하다. 판넬/성별/사이즈의 90% 확인 기준에 걸린 사진은 18 → 7장이며, 이는 카테고리와 아동 성별까지 포함한 전체 앱의 검수 필요 수와 다르다.

판넬 위치·성별/연령 확률·카테고리 결과는 140장의 280회 실행에서 차이가 없었다. 카테고리 정답은 양쪽 동일하게 실사 120/130이며, 사이즈 100%를 전체 앱 정확도라고 해석하지 않는다. 추론 실패는 0건이다. ## 설치파일과 실제 설치본

- 설치파일: `설치파일/CoatDesk-2.6.4-Setup.exe`
- 크기: 477,231,542바이트 (약 455.1 MiB)
- SHA-256: `7a060dee49febe25a835fad0210864c417c0fc720e90f2fb05e1cc8ef73d0ab5`
- 빌드: `dist-releases/v2-06ed991f2e05/build-report.json`, CPU PyTorch 및 기존 2.6.3과 같은 패키지 버전.
- 제한된 실행 환경에서 32비트 NSIS 시작이 WinError 623으로 실패해, 완료된 PyInstaller 앱을 그대로 두고 동일 NSIS 포장 명령만 제한 밖에서 재실행했다. 설치 스크립트는 변경하지 않았다.
- `/SANDBOX /S`로 프로젝트 안의 새 검증 폴더에 설치했고, 실제 설치 등록 정보가 바뀌지 않은 것을 확인했다. 설치된 5,541개 파일이 빌드본과 해시 일치했다. 기존 2.6.3 설치파일도 해시가 같다. UI/QML·다른 모델·정책·변환표·엑셀 양식·아이콘 38파일을 기존 배포본과 별도로 대조했다.
- 설치된 `CoatDesk2.exe`가 별도 DB에서 실사 130장·합성 10장을 모두 처리했고, 앞서 측정한 원문 사이즈·입력 사이즈·카테고리와 140장 모두 일치했다. QML 경고와 실행 오류는 0건이다. 시작·폴더 검사·UI·DB 저장을 포함한 전체 실행은 **117.08초**이며, 위 CPU 추론 평균과 다른 측정이다.
- 검증 DB의 140장을 확인 처리한 뒤 실제 앱을 다시 실행해 분석했다. 입력·출처·확인 값·캐시 키·예측이 전부 유지됐고 전체 실행은 13.01초였다. 이 확인 처리는 검증 DB에만 적용했다.
- 같은 설치본에서 엑셀을 두 번 저장해 `20261122`, `20261122 (2)` 시트의 코드·카테고리·사이즈 140행씩을 대조했다. 두 번째 저장 후 첫 시트 XML 해시도 같았다. 사용자의 기존 엑셀은 쓰지 않았다.
- 설치본의 라이트 작업 화면과 라이트·다크 홈 화면을 소프트웨어 렌더링으로 실행·캡처하고 육안 확인했다. QML 경고는 없었다. 이 검사는 Windows 네이티브 제목 표시줄의 동작이나 다른 PC에서의 실행까지 검증한 것은 아니다.

이 설치 검증 단계에서는 기존 설치 위의 업데이트, 사용자 DB 쓰기, 커밋·푸시·외부 배포를 하지 않았다. 이후 2026-11-23 사용자가 프로젝트 마무리와 소스·문서 Git 반영을 별도로 요청했다. `실행2.cmd`의 기존 최신 빌드 포인터와 원본 `resources/ai`는 보존한다. 재빌드에는 `scripts/prepare_size20_runtime.py`로 실제 2.6.3 배포 자산 위에 선택 가중치만 새 폴더로 준비하고, 그 폴더를 `scripts/build_v2.py --ai-assets`에 지정한다.
