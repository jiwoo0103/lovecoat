## 후속 2.2 QML 통합 (2026-10-27)

아래 HTML 확정 기록을 기준으로 실제 QML 화면에 적용했습니다. 홈 카드·작업 모달·하단 작업 탭·작업공간 메뉴·세 조건 AND 필터·사진 보기·카드 단일 필수검수 버튼·내장 양식 전송 UI를 연결했습니다. `test_v2_qml.py`와 `test_v2_ui_flow.py` 총 6개에서 실제 클릭·키 입력·작업 전환·작은 창·가짜 API 전송을 검증했고 QML 경고가 없습니다. 누락 글리프는 햄버거 3개 Rectangle 등으로 보완했습니다.

관리자는 실제 사진 4벌과 CPU 모델로 소스 앱 실행/분석도 확인했습니다. 설치물 검증은 진행 요약을 기준으로 합니다. 아래의 ‘QML 미적용’은 HTML 초안 확정 시점의 이력입니다.

사용자가 현재 HTML 화면을 **초안으로 확정**하고, 추가 세부 수정은 나중에 진행하기로 했다. 이번 결과는 화면·사용 흐름의 합의이며 실행 앱의 구현 완료를 뜻하지 않는다.

## 승인된 화면

- 시작 화면은 홈. 작업 카드를 바둑판 형태로 배치하고 첫 카드는 **+ 새 작업 만들기**, 이후 카드는 기존 작업이다.
- 새 작업 입력란은 처음부터 노출하지 않고 + 카드를 눌렀을 때 연다. 프로그램 이름 클릭은 홈 이동이다.
- 작업 화면 하단에는 열린 작업 탭과 + 버튼을 둔다. +에서 새 작업 만들기 또는 기존 작업 열기를 선택한다. 동일 작업은 중복 탭을 만들지 않는다.
- 작업공간 제목 줄의 오른쪽, 자동 저장 옆에 **햄버거 메뉴**를 둔다. 프로그램 이름이 있는 최상단 헤더에는 두지 않는다.
- 작업 도구 줄 왼쪽은 **분석 · 확인 필요**, 오른쪽은 **옷 번호 검색 · 분류**이다. 버튼 이름은 AI 분석이 아닌 **분석**이다.
- 분류 버튼 하나를 누르면 **성별 / 사이즈 / 성인·아동**을 세 줄로 펼친다. 각 항목은 전체 또는 하나의 값을 고르며 최대 세 조건을 AND로 적용한다. 번호 검색·확인 필요 필터와도 함께 적용한다.
- 성별 필터의 남성/남아와 여성/여아는 같은 성별 그룹으로 표시하며 성인·아동 조건으로 연령을 좁힌다.
- **사진만 보기**는 기본 OFF이며 기존 사진+입력란 화면이 기본이다. 스위치는 작게 만들어 하단 페이지 이동 줄 오른쪽에 둔다. 별도 줄을 늘려 사진 영역을 줄이지 않는다.
- 드물게 쓰는 재분석·점수 기준·보기 설정·사진 폴더/번호 설정·시트 전송은 작업공간 햄버거 메뉴 안에 둔다.

## AI 자동 입력과 사용자 확인 — 최종 합의

1. 분석 결과는 사진 옆 입력란의 **빈 항목에 즉시 자동 입력**한다. 별도 제안 적용 버튼을 요구하지 않는다. 이미 입력된 값은 재분석에서도 덮어쓰지 않는다.
2. 기준 미달 결과도 후보 값이 있으면 먼저 입력한다. 예: 성별 점수 70이 기준 미달이어도 남성 후보를 입력해 두고 확인 필요로 표시한다. 옷 분류·사이즈도 같은 흐름이다. 후보를 얻지 못한 경우에는 값을 만들어 넣지 않고 미입력/확인 필요로 남겨야 한다.
3. **아동은 성별이 비어 있으면 남아로 먼저 입력하되 반드시 사용자가 확인**한다. 남아가 맞으면 수정 없이 확인만 누르고, 여아면 값을 바꾼 뒤 확인한다. 이미 입력된 값은 보존한다.
4. 기준을 충족한 일반 항목/옷은 사람의 확인을 요구하지 않는다. 모든 옷을 하나씩 검수하거나 전체 옷에 확인 완료를 요구하는 기존 흐름은 사용하지 않는다.
5. 확인 필요한 값은 노란색 등으로 강조한다. 값 아래에 각각 확인 버튼을 두지 않고 **카드 오른쪽 입력란 바로 아래의 확인 버튼 하나**로 해당 옷의 미확인 항목을 한 번에 처리한다. 사진 아래 별도 전체 폭의 버튼 줄을 만들어 카드 높이를 늘리지 않는다.
6. 확인 필요한 값을 수정한 것만으로 검수가 끝나지는 않는다. 카드의 확인을 눌러야 확인 필요 목록에서 빠진다. 확인 후 해당 확인 대상 값을 다시 바꾸면 확인 필요로 되돌리는 동작을 초안에서 확인했다.
7. 자동 입력된 정상 카드에는 'AI 결과가 바로 입력되었습니다' 같은 안내 문구나 확인 버튼을 표시하지 않는다.
8. 전송 조건은 **필수 값의 완성 + 확인이 필요한 항목의 확인 처리 완료**이다. 기존의 모든 `Garment.confirmed`가 참이어야 하는 조건과 구분해야 한다. 값이 들어 있다는 이유만으로 기준 미달/아동 성별 검수를 생략해서는 안 된다.

위 내용은 중간 대화의 '확인 기능 제거', '낮은 점수는 빈칸 유지', '아동 성별은 비워두기'보다 나중에 확정한 요구사항이다. 중간 해석을 최종 요구로 사용하지 않는다. 확인은 **기준 미달 항목과 아동 성별에만 필수**이다.

## 연결 및 통합 시 주의

- 현재 실행 앱은 `coatdesk_v2`의 PySide6/Qt Quick/QML이다. HTML은 배치 확인용이며 앱을 웹 프레임워크로 교체하기로 합의한 것이 아니다.
- 현재 `RecognitionEngine`은 낮은 점수의 값을 `values`에서 빼는 경로가 있으므로, 통합 시 후보·점수·보류 이유를 이용해 위 자동 입력과 확인 상태를 연결해야 한다. UI의 노란 표시와 저장/전송상의 확인 필요 상태가 일치해야 한다.
- 입력값과 사용자 확인 상태는 구분해서 관리해야 한다. 자동 입력된 값도 미검수 상태일 수 있다. 필드 출처/점수/검수 기록의 구체적인 저장 계약과 마이그레이션은 관리자·AI 담당과 조율한다. 이번 UI 초안에서 새 DB 스키마를 구현하지 않았다.
- 옷 분류 모델의 앱 연결, 실제 보류 임계값·정확도·속도는 별도 담당 결과를 기준으로 한다. 화면의 70/72/78 점수는 **가상 예시**이다.
- Google 인증/API 내부 구현은 변경하지 않았다. 관리자 채팅의 최신 합의인 내장 표준 양식 기반 새 탭 생성 흐름을 따라 후속 전송 UI를 연결해야 한다. HTML은 실제 계정/대상 URL/양식 선택을 구현한 상태가 아니다.
- 작업 전환 시 값·확인 상태가 다른 작업에 섞이지 않아야 한다. 초안에는 작업별 메모리 상태와 탭 전환 예시만 있다. 실제 앱의 SQLite 저장·재실행 복원·백그라운드 작업 안전성은 통합 검증이 필요하다.
- 과거 기록의 `Main.qml:284~286` 실행 차단 오류는 활성 앱 소스에 이번 초안을 반영하면서 해결한 것이 아니다. 최종 통합 시 별도로 수정·실행 검증해야 한다.

## 확인한 범위와 미검증 사항

- HTML/JavaScript 문법 검사, 브라우저 육안 확인 및 실제 클릭 확인을 수행했다.
- 홈/작업 이동, 새 작업 모달/가상 탭 생성, 기존 작업 열기, 탭별 입력 보존, 번호 검색과 세 분류의 AND 조합, 확인 필요 필터, 사진만 보기, 사진 확대를 확인했다.
- 한 옷의 여러 확인 대상 값을 한 번에 처리하는 동작, 수정 시 확인 필요 복귀, 아동 남아 기본값을 바꾸지 않고 확인하는 동작을 확인했다.
- 분석 예시에서 기존 입력을 보존하고 빈칸만 채우는 동작과, 확인 필요 항목을 모두 처리한 후 가상 전송 미리보기 메뉴가 활성화되는 동작을 확인했다.
- 최종 변경은 햄버거 메뉴를 작업공간 제목 줄로 내린 것이며 메뉴 펼침 동작도 확인했다.
- 이번 확정본을 실제 QML 앱에 적용하거나 전체 앱 테스트·빌드·설치 검증·실제 AI 분석·Google 온라인 전송을 수행하지 않았다. 커밋·푸시도 하지 않았다.
- 앞서 잠시 만든 QML 홈/탭 시안은 사용자가 HTML 검토 우선으로 방향을 바꿨을 때 `.local/ui-home-tabs-implementation-draft/`에 보존하고 활성 소스를 원복했다. 당시 테스트 29개 통과 기록은 **현재 확정 HTML의 QML 구현 검증 결과가 아니다**. 해당 과거 시안은 최종 승인본으로 사용하지 않는다.

관리자는 이 승인본을 후속 통합 기준으로 사용하며, 추가 UI 세부 개선은 사용자와 나중에 조정한다.
