# 외투 작업실

> **이전 버전 사용법 보존본:** 설치형 새 버전은 [현재 README](../README.md), 재구축 합의 사항은 [REBUILD_HANDOFF.md](../REBUILD_HANDOFF.md)를 참고하세요. 이 본문은 기존 Qt Widgets/JSON 프로토타입의 사용법입니다.

번호별 폴더의 옷 사진을 바로 모아 보고, 입력한 값을 기존 Google Sheets 양식에 반영하는 Windows 앱입니다.
Python + PySide6로 구현했습니다. 별도 서버나 유료 AI API를 사용하지 않습니다.

## 실행

exe를 실행하면 **바탕화면/외투 작업실 작업** 폴더를 만들고, 실행 파일과 `_internal`을 그 안에 자동 복사합니다.
원래 위치의 파일은 그대로 두며 동일한 파일은 다시 복사하지 않습니다. 복사 중에는 창 아래에 진행 상태를 표시합니다.
이후에는 바탕화면 폴더의 **`외투 작업실.exe`**를 더블클릭하세요. 그 폴더에서 실행하면 자기 자신을 다시 복사하지 않습니다.
같은 폴더의 `_internal`은 실행에 필요한 파일입니다. exe와 함께 보관하세요. 작업 JSON도 이 폴더에 저장됩니다.

프로젝트의 **`실행.cmd`**를 더블클릭하세요. `dist-releases/latest.txt`에 기록된 최신 빌드를 엽니다.
다른 PC로 옮길 때는 해당 빌드의 **`CoatDesk` 폴더 전체**를 복사하고 내부 `CoatDesk.exe`를 실행하세요.
OCR 실행 파일과 영어 인식 모델을 포함합니다. 대상 PC에서 Python을 설치할 필요가 없습니다.

1. **사진 폴더 불러오기** → `0_0001`, `0_0002` 같은 폴더들을 포함하는 상위 폴더를 선택합니다.
2. 작업 파일(`*.coat.json`)은 **바탕화면/외투 작업실 작업** 폴더에 자동 저장됩니다. 촬영일을 확인합니다.
3. **한 벌씩 3장** 또는 **정면만 모아보기**로 바로 작업합니다. **보기 설정**에서 줄 수(1~8줄)와 사진 크기를 조절합니다.
4. 오른쪽 **옷 정보** 탭에서 카테고리·남성/여성·성인/유아동·사이즈를 고르고 **선택한 n벌에 적용**을 누릅니다.
5. **더보기 → Google 연결 설정**에서 연결한 뒤 상단 **시트로 보내기**에서 대상과 변경값을 확인하고 전송합니다.

오른쪽은 **옷 정보 / 사진 인식** 두 탭입니다. 입력 패널은 사진 위의 **입력 패널 접기/열기**로 숨기거나 펼칩니다.
페이지 이동과 선택·입력 완료 수, 자동 저장 상태는 하단에 표시합니다. 수동 저장은 더보기 또는 Ctrl+S로도 가능합니다.
**작업 열기**는 촬영일·사진 폴더·옷 수·최근 저장 시간을 보여주는 목록입니다. 기존 JSON은 **다른 작업 파일 찾기**로 열 수 있습니다.

사진을 따로 모아 전달할 때만 **더보기 → 사진 한 폴더로 내보내기**를 사용하세요.
사진 보기·인식·시트 입력에는 사진 복사나 이름 변경이 필요하지 않습니다. 도움말도 더보기 메뉴에 있습니다.

사진 더블클릭: 확대 / 마우스 휠: 확대·축소 / 드래그: 이동.
**보기 설정 → 사진 크기**는 기본 150%, 100~250%로 조절하며 작업별로 저장됩니다.
확대 시 가장자리가 가려질 수 있습니다. 전체 구도는 100% 또는 더블클릭한 확대 창에서 확인하세요.
사진 목록을 클릭한 뒤 **←/↑는 이전 페이지, →/↓는 다음 페이지**입니다.
목록에서 **왼쪽으로 드래그하면 다음, 오른쪽으로 드래그하면 이전 페이지**로 이동합니다.
드래그로 페이지를 넘길 때 기존 선택은 유지됩니다. 입력란 안의 방향키는 입력 조작에 사용됩니다.
Shift+클릭: 연속 선택 / Ctrl+클릭: 여러 벌 선택 / Ctrl+F: 외투코드 검색.
Page Up/Down: 페이지 이동 / Ctrl+S: 저장 / Ctrl+Z: 앱 안의 입력 취소.

## 사진 및 번호 규칙

- `0_1001/img_0_0_0.jpg` → `0_1001_0.jpg`. 폴더 이름의 앞자리 0을 유지합니다.
- 원본은 변경하지 않습니다. 이름과 내용이 동일한 출력은 건너뜁니다.
- 같은 이름에 내용이 다르면 복사를 중단합니다. 덮어쓰지 않습니다.
- 입력 구조: `0_숫자` 폴더 안 `img_0_0_숫자.jpg/jpeg/png/webp/bmp`.
  다른 이름, 누락, 손상, 추가 각도를 검사해서 표시합니다.
- 기본 정면은 0번입니다. 선택한 옷의 정면 사진을 변경할 수 있습니다.
- 3장 보기에서 누락된 사진은 빈칸으로 남습니다. 추가 각도도 복사되며 정면으로 지정해 볼 수 있습니다.
- 외투코드는 원본 폴더에서 가져옵니다. 코드 사이의 빈 번호를 만들어 넣지 않습니다.
- 왼쪽 `번호`는 해당 날짜에 사용할 옷만 연속 순번입니다.
  앱의 `#번호`는 현재 로컬 작업 기준이고, 시트에 추가할 때는 시트의 마지막 번호부터 이어집니다.
- 앱에서 제외하면 새 시트 입력에서 제외됩니다. 사진은 보존·복사하며 이미 시트에 있는 행은 삭제하지 않습니다.

## 인식 사용법과 현재 범위

1. **사진 인식 → 인식 설정 열기 → 머리 확대**로 기본 영역이 머리 전체와 글자를 포함하는지 확인합니다.
2. 위치가 다르면 **머리 영역 지정**에서 드래그합니다. 같은 위치를 다른 옷에도 적용할 수 있습니다.
3. **선택 인식/전체 인식**을 실행합니다.
4. 사이즈는 로컬 Tesseract OCR로 읽습니다. 얼굴 안의 글자 후보를 잘라 기울기를 바꿔 읽고, 서로 다른 결과가 나오면 확정하지 않습니다.
5. 머리 분류는 먼저 남성/여성·성인/유아동을 직접 확인·적용한 뒤 **현재 머리를 기준으로 등록**합니다.
   등록한 머리 모양과 비교해 분류를 제안합니다. 기준은 작업 파일에 저장되며 해당 작업 안에서 사용됩니다.
6. **인식 제안 확인·적용**에서 확인합니다. 인식만 실행하면 입력값/시트는 바뀌지 않습니다.
   이미 사람이 입력한 값은 제안을 적용하거나 재인식해도 덮어쓰지 않습니다.

머리 모양 비교는 글자 영역을 가린 초기 비교 방식입니다. AI 이미지 분류 모델과의 성능 비교는 아직 하지 않았습니다.
남성·아동 등 각 머리 유형의 확인된 사진이 필요합니다. 유사도와 OCR 점수는 확률이나 정확도 보장 수치가 아닙니다.
카테고리 자동 판정, 의류 실측 입력은 포함하지 않습니다.

크기/머리 변화가 의심되면 앞뒤 두 벌에 **경계 후보**를 표시하고 배경을 연한 주황색으로 강조합니다.
선택한 경계 후보에도 주황색 배경을 유지하며 파란 선택 테두리를 함께 표시합니다. 제외한 옷은 회색으로 표시합니다.
모양 경계는 조명·위치·기울기 때문에 과하게 표시될 수 있습니다.
읽지 못한 구간에 이전 값을 자동 전파하지 않습니다. 직접 확인하고 범위 선택·일괄 적용하세요.
새 사이즈 표기나 촬영 방식은 추가 사진으로 검증해야 합니다.

## Google Sheets 연결

처음 한 번 사용자 계정으로 다음 설정이 필요합니다.

1. Google Cloud 콘솔에서 프로젝트를 준비하고 **Google Sheets API**를 사용 설정합니다.
2. Google Auth Platform에서 동의 화면을 설정하고, 테스트 모드라면 사용할 계정을 테스트 사용자로 등록합니다.
3. OAuth 클라이언트 유형 **데스크톱 앱**을 만들고 JSON을 다운로드합니다.
4. 앱의 **Google 연결 설정**에서 해당 JSON을 선택하고 브라우저로 로그인합니다.
5. **시트로 보내기**에서 주소를 입력하고 **시트 불러오기**를 누릅니다. 촬영일과 같은 기존 날짜 탭을 자동 선택해 변경 미리보기를 보여줍니다.
6. 같은 창에서 대상 날짜·사용/제외 옷 수·새 옷/기존 옷 수정 수·변경값을 확인하고 **확인한 내용으로 입력**을 누릅니다.
   주소나 날짜 탭을 바꾸면 이전 미리보기는 폐기합니다. 다시 미리보기를 만든 뒤 전송해야 합니다.

기존 `YYYYMMDD` 날짜 탭을 사용합니다. 앱에서 촬영일과 탭 이름이 같아야 합니다.
새 날짜 탭은 Google Sheets에서 기존 양식을 복제해 빈 입력 행을 준비하세요.
OAuth JSON이나 로그인 파일은 저장소에 올리지 마세요.
로그인 토큰은 Windows DPAPI로 암호화해 앱 데이터 폴더에 저장합니다.
테스트 모드 OAuth 앱은 Google 정책에 따라 재로그인이 필요할 수 있습니다.

지원 양식의 2행 헤더:

| 열 | 항목 | 처리 |
|---|---|---|
| B | 번호 | 새 행만 날짜 내 연속 순번 |
| C | 외투코드 | 새 행만 문자열로 입력, 앞자리 0 보존 |
| D | 이미지 | 기존 수식 유지; 빈 새 셀은 기존 이미지 수식 복사 |
| E | 카테고리 | 사람이 입력한 값만 |
| G | 남성/여성 | 확인·적용한 값만 |
| H | 성인/유아동 | 확인·적용한 값만 |
| I | 사이즈 | 확인·적용한 값만 |

F, J:N 등 다른 값과 기존 수식은 수정하지 않습니다. 기존 셀은 `userEnteredValue` 필드만 갱신하므로 서식을 다시 쓰지 않습니다.
D의 지원 수식은 `=IF(C3<>"", "0_" & C3, "")` 또는 `="0_" & C3`처럼 해당 행 C를 참조하는 원본 규칙입니다.
실제 사진 업로드/삽입 기능은 아니며, 기존처럼 이미지 식별자 `0_외투코드`를 생성합니다.

- 같은 날짜 탭에서 외투코드로 기존 행을 찾습니다. 이미 있는 행의 번호·코드는 유지합니다.
- 앱의 빈 항목은 기존 시트 값을 지우지 않습니다. 기존 수식 셀에 값을 덮어쓰려 하면 중단합니다.
- 고정 목록 드롭다운을 검사합니다. 지원하지 않는 유효성 검사, 보호 범위, 병합 셀, 중복 코드,
  부분 입력된 새 행, 다른 헤더/이미지 수식이면 중단하고 사유를 표시합니다.
- 미리 서식이 있는 빈 행을 사용합니다. 시트 끝을 넘으면 미리보기에 행 확장을 표시하고,
  기준 행의 서식·유효성 검사·행 높이와 이미지 수식을 이어 갑니다. 끝까지 적용된 조건부 서식 범위도 연장합니다.
  다른 열에 알 수 없는 수식이 있는 확장 기준은 자동 확장을 중단합니다.
- 전송 직전에 다시 읽어 변경을 검사하고, 전송 후 값을 다시 확인합니다.
  Google API의 원자적 일괄 요청을 사용하지만 **읽기와 쓰기 사이 동시 편집까지 막는 잠금은 아닙니다**.
- 통신 오류가 나면 전송을 무작정 반복하지 않습니다. 새 미리보기를 만들어 반영 여부를 확인하세요.
- Ctrl+Z는 이미 전송한 시트를 되돌리지 않습니다. 시트의 수정 내역으로 복구하세요.

현재 실제 Google 계정/시트가 제공되지 않아 OAuth 로그인과 실서식 전송은 아직 실환경 검증하지 않았습니다.
처음에는 실제 파일의 복사본에서 미리보기와 입력을 확인하세요.

## 작업 저장

새로 불러온 작업은 바탕화면의 **외투 작업실 작업** 폴더에 `.coat.json` 파일로 자동 저장됩니다.
처음 불러올 때 저장 위치를 묻지 않으며, 파일 이름은 촬영일·원본 폴더 이름·고유 번호로 만들어 기존 작업을 덮어쓰지 않습니다.
‘작업 열기’는 이 폴더의 작업과 최근에 연 작업을 날짜·폴더 이름으로 보여줍니다.
기존에 다른 위치에 저장한 작업도 열 수 있으며 그 작업은 기존 위치에 계속 저장됩니다.
작업 파일에는 사진 경로, 입력값, 제외 상태, 정면/머리 영역,
인식 결과, 기준 모양, 페이지와 선택 상태를 포함합니다. 사진 자체는 작업 파일에 넣지 않습니다.
원본 사진을 옮기면 경로가 끊기므로 현재 작업이 끝날 때까지 원본 폴더 위치를 유지하세요.
설정/로그인 정보는 Windows의 앱 로컬 데이터 폴더(CoatDesk)에 저장합니다.
작업 파일은 임시 파일을 완전히 쓴 뒤 교체합니다.

## 개발 및 검증

Python 3.12, Windows 64비트에서 개발했습니다. 시스템 전역 설치 없이 가상환경을 사용합니다.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m coatdesk
.\scripts\test.ps1
.\.venv\Scripts\python.exe scripts\build.py
.\scripts\install_desktop.ps1
```

Tesseract는 `vendor/tesseract/tesseract.exe` 및 필요한 DLL, `tessdata/eng.traineddata`,
`tessdata/configs/tsv`를 준비합니다. 빌드 결과에는 이미 포함되어 있습니다.
다운로드 출처는 `THIRD_PARTY_NOTICES.md`에 기록했습니다.
앱은 한글 경로 문제를 피하도록 OCR 실행 시 상대 `tessdata` 경로를 사용합니다.

`scripts/verify_sample.py <사진원본폴더> <프로젝트 안 검증폴더>`는 사진 복사/재실행/원본 해시와 OCR 결과를 확인합니다.
빌드는 매번 `dist-releases` 아래 새 폴더에 생성하고 성공한 뒤 최신 실행 경로를 갱신합니다.
바탕화면 설치본을 갱신할 때는 기존 앱을 닫고 최신 빌드의 exe를 실행하세요. 변경된 실행 파일을 자동 복사하며 작업 JSON은 보존합니다.
`scripts/install_desktop.ps1`은 개발 중 수동 복사가 필요할 때 사용할 수 있습니다.
기존에 실행 중인 앱의 파일을 덮어쓰지 않으며, 업데이트 적용은 앱을 닫고 `실행.cmd`를 다시 실행하면 됩니다.
검증 산출물은 `.local/validation`에 있습니다. 샘플 13벌은 개발 중 조정에도 사용했으므로 별도 평가 데이터가 아닙니다.

구조:

- `domain.py`: 작업·입력값·순번·자동 저장·경계
- `desktop.py`: exe 실행 시 바탕화면 폴더 생성·실행 파일과 필수 파일 자동 복사·중복 건너뛰기
- `photos.py`: 폴더 검사·복사 계획·중복 및 무결성 검사
- `recognition.py`: 글자 영역 추출·Tesseract OCR·머리 모양 비교
- `sheets.py`: Google 인증·읽기·변경 계획·충돌 검사·전송
- `widgets.py`, `window.py`: 사진 뷰어·선택·입력 UI와 백그라운드 작업
- `recent.py`, `dialogs.py`: 최근 작업 목록, 한 창에서 확인하는 시트 전송
