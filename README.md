Windows 설치형 사진 검수 프로그램입니다. **작업공간 만들기 → 분석 → 검수·수정 → 새 Google 시트 탭 전송** 순서로 사용합니다.

## 실행과 설치

- 개발 폴더에서는 `실행2.cmd`가 `dist-releases/latest-v2.txt`에 기록된 최신 빌드를 실행합니다.
- 다른 PC에는 빌드 폴더의 `CoatDesk-2.2.0-Setup.exe`를 전달해 설치합니다. Windows 10/11 64비트용이며 Python·Tesseract·GPU를 따로 설치할 필요가 없습니다. CPU 실행 환경과 기존 학습 모델 3개를 함께 포함합니다. 다른 PC 실물 검증은 별도입니다.
- 시작 메뉴의 **외투 작업실 2**로 실행합니다. 화면 표시 문제가 있으면 같은 메뉴의 **호환 모드**를 사용합니다.
- 프로그램을 종료하고 새 설치파일을 실행하면 업데이트됩니다. 제거·업데이트는 작업 기록과 원본 사진을 삭제하지 않습니다.
- 바탕화면 바로가기는 설치할 때 선택합니다. 앱 실행이 바탕화면 작업 폴더나 exe 복사본을 만들지 않습니다.

프로그램 기본 위치는 `%LOCALAPPDATA%\Programs\CoatDesk`, 작업 DB·설정·암호화된 로그인 정보는 `%LOCALAPPDATA%\CoatDesk\v2`입니다.
사진은 원래 폴더에서 읽으며 DB에 사진 파일을 넣지 않습니다. 첫 버전은 같은 PC에서 이어서 작업하는 용도입니다.

> 배포용 Desktop Google 연결 설정을 포함합니다. 담당자는 각자 로그인하며 로그인 토큰은 설치물에 포함하지 않습니다. 현재 Google 프로젝트는 테스트 모드여서 등록한 테스트 사용자만 로그인할 수 있습니다. 2.2 내장 양식으로 가상 1벌을 새 검증 탭에 실제 전송하고 헤더·서식·수식·입력값을 재조회했습니다. 설치 환경에서의 새 사용자 로그인과 다른 PC 검증은 별도입니다.

## 작업공간 만들기

1. 홈의 **+ 새 작업** 카드를 눌러 이름과 촬영일을 입력합니다. 이름을 `20261024`처럼 입력하면 촬영일을 제안합니다. 기존 작업 카드나 하단 탭으로 작업을 전환합니다.
2. `0_0001`, `0_0002` 같은 폴더가 들어 있는 사진 상위 폴더를 선택합니다.
3. 사용할 시작·끝 번호와 에러번호를 입력합니다. 예를 들어 1~400번, 에러 212·300이면 실제 폴더가 모두 있을 때 398벌을 사용합니다.
4. **사진 검사하고 만들기**를 누릅니다. 사진 누락·손상을 표시하며 없는 번호를 만들어 넣지 않습니다.

폴더 구조는 `0_0001/img_0_0_0.jpg`, `img_0_0_1.jpg`, `img_0_0_2.jpg` 형식입니다. JPG/JPEG/PNG/WebP/BMP를 지원합니다.
외투코드의 앞자리 0을 유지하며 원본 파일을 복사·이동·이름 변경하지 않습니다.
작업 중에는 **에러번호 / 사진 폴더**에서 제외번호를 바꾸거나 옮긴 사진 폴더를 다시 연결할 수 있습니다.
범위 밖의 에러번호는 안내하며 다른 날짜 작업공간이나 이미 전송한 시트를 자동으로 수정하지 않습니다.

## 검수와 입력

- 기본은 정면 사진과 입력란을 함께 보여주는 4벌 화면입니다. **보기 설정**에서 2벌 보기로 바꿀 수 있습니다.
- 사진 클릭: 한 벌 선택. Ctrl+클릭: 선택 추가·해제. Shift+클릭: 연속 선택.
- 카드에서 카테고리·성별·성인/유아동·사이즈를 입력하거나 **일괄 입력**으로 선택한 여러 벌에 적용합니다.
- 사이즈는 직접 입력하거나 목록에서 고릅니다. 직접 입력한 값은 입력란을 벗어날 때 저장됩니다.
- 낮은 점수의 값과 아동 성별에만 필수 확인을 요구합니다. 해당 카드의 **확인** 버튼으로 여러 확인 대상 항목을 한 번에 처리합니다. 값을 수정한 것만으로 필수 검수가 끝나지 않으며, 확인한 대상 값을 다시 바꾸면 재확인이 필요합니다.
- 기준을 충족한 일반 항목은 별도 확인 없이 필수 값이 완성되면 전송할 수 있습니다. 카테고리는 수동 입력합니다. **실행 취소 / Ctrl+Z**는 입력과 검수 상태를 함께 되돌립니다.
- 옷 번호 검색과 **분류**의 성별·사이즈·성인/아동 조건은 AND로 적용됩니다. **확인 필요**를 켜면 처리할 항목을 좁힐 수 있습니다.
- 입력과 검수 상태는 SQLite에 자동 저장됩니다. 재실행 시 홈에서 시작하며 열려 있던 작업 탭과 작업별 보기·현재 옷·선택 상태를 복원합니다. 저장 실패 메시지가 나오면 저장 위치를 확인하세요.

## 사진 전용 보기와 인식

**사진만 보기**는 정면 기본이며 보기 설정에서 한 벌당 3장 묶음·줄 수·사진 크기를 조절할 수 있습니다.
사진 더블클릭 또는 **상세 / 다른 각도**에서 확대합니다. 휠로 확대·축소하고 확대 중 드래그로 이동합니다.
목록의 방향키·좌우 드래그는 페이지 이동, 상세 화면의 방향키는 이전·다음 옷 이동입니다. 입력란에서는 입력 조작을 우선합니다.

1. **분석**을 누릅니다. AI가 정면 사진에서 판넬 전체를 찾고, 판넬 사진으로 남성/여성/아동과 사이즈를 각각 분석합니다. 현재 페이지부터 분석하며 완료된 옷부터 확인할 수 있습니다.
2. **AI 보류 기준**에서 판넬·성별·사이즈 기준을 바꿀 수 있습니다. 기본값은 각각 **50%·95%·95%**입니다. 점수는 모델의 판단 강도이며 실제 정답률이 아닙니다.
3. 후보가 있으면 기준 미달이어도 입력란의 빈 항목에 바로 입력하며 노란색 등으로 확인 필요를 표시합니다. 기존 값은 재분석에서도 덮어쓰지 않습니다. 후보 영역조차 없으면 임의 값을 넣지 않습니다. **머리 확대**나 **머리 영역 지정**으로 확인·재분석할 수 있습니다.
4. 아동 성별은 비어 있으면 남아(남성)로 입력하고 반드시 확인합니다. 여아면 여성으로 바꾼 뒤 확인합니다. 정상 항목에는 별도 제안 적용이나 확인 버튼이 필요하지 않습니다.

**분석 중단**은 현재 한 벌의 처리를 마친 후 멈추고 결과를 보존합니다. 원본·영역·보류 기준·모델이 같은 완료 결과는 이어서 분석할 때 재사용합니다.
**다시 분석**은 완료 결과도 다시 계산합니다. 재분석 역시 사람의 입력을 덮어쓰지 않습니다.
이 버전은 학습한 판넬 위치 모델 1개와 판넬 입력 분류 모델 2개를 CPU로 실행합니다. 카테고리는 수동 입력합니다. 아동 숫자는 확보한 엑셀 대응표로 사이즈를 바꾸며, 아동 성별은 사용자 지시에 따라 모두 남아로 임시 지정합니다. 아동 남녀를 따로 학습한 모델은 아닙니다.
후보를 얻지 못한 항목은 비워 두며 실패를 카테고리 ‘기타’로 바꾸지 않습니다. 점수와 경계 표시는 확정 정답이나 정확도 보장이 아닙니다.

## Google 연결 준비 (관리자)

배포 관리자가 한 번 데스크톱 앱용 OAuth 클라이언트를 준비합니다. 담당자마다 Cloud 프로젝트를 만들 필요는 없습니다.

1. Google Cloud 프로젝트에서 Sheets API와 OAuth 동의 화면·Desktop 앱 클라이언트를 설정합니다. 결제나 유료 확장을 자동 활성화하지 않습니다.
2. 이 버전은 URL로 지정한 파일에 접근하기 위해 `https://www.googleapis.com/auth/spreadsheets` 범위를 사용합니다. 이 권한은 새 탭 하나로만 제한되는 권한이 아닙니다.
3. 개발 시에는 **Google 시트로 보내기 → 관리자 연결 설정**에서 연결 JSON을 선택합니다. 배포 빌드에는 `build_v2.py --oauth-client`로 Desktop 클라이언트 설정을 포함할 수 있습니다.
4. 일반 담당자는 **Google 로그인**을 눌러 본인 브라우저에서 승인합니다. 사용자 토큰·서비스 계정 개인키를 설치파일에 넣지 않습니다.
5. 장기 배포 전에 실제 계정 구성에 맞는 게시·검증 요건을 완료합니다. 테스트 사용자와 갱신 토큰 만료 제한이 있는 OAuth 테스트 모드를 장기 배포 상태로 두지 않습니다.

로그인은 시스템 브라우저·루프백 콜백·PKCE를 사용하며 토큰은 Windows DPAPI로 암호화합니다.
로그인한 계정이 대상 파일을 편집할 수 있어야 합니다. 실제 계정·테스트용 시트 검증은 배포 전 별도로 필요합니다.

## 새 시트 탭으로 전송

1. 작업공간 메뉴의 **Google 시트로 보내기**에서 본인 Google 계정으로 로그인합니다.
2. 대상 URL을 입력하고 연결합니다. 대상 문서에 양식 탭이 없어도 됩니다.
3. 새 탭 이름을 지정하고 미리보기를 만듭니다. 기본 이름은 촬영일이며 중복이면 `(2)`, `(3)`을 붙입니다. 모든 필수 값과 필요한 검수를 완료해야 합니다.
4. URL·최종 새 탭 이름·대상/제외/누락 수량과 입력 내용을 확인하고 명시적으로 전송합니다.

항상 새 탭을 생성하며 기존 날짜 탭·원본 양식에 값을 덮어쓰지 않습니다. 수정본을 다시 내보내도 새 탭입니다.
새 탭의 B열 번호는 1부터 연속, C열 코드는 원래 문자열입니다. D열은 `0_0001` 같은 사진 식별자를 만드는 수식이며 실제 사진 업로드는 하지 않습니다.
예시 입력을 비우고 E/G/H/I 업무 값과 D/K:N 수식을 적용합니다. F/J는 비운 상태로 두고 헤더·P:R 보조 목록·서식·드롭다운·열 너비는 유지합니다.
표준 양식은 원본 엑셀의 `양식예시(복사해서 사용)`을 기반으로 내장하며 실제 옷 데이터·예시값은 포함하지 않습니다.

새 탭 생성·서식·입력을 하나의 원자적 요청으로 보내며 전송 후 다시 읽어 확인합니다. 기존 탭 쓰기·삭제·문서 전역 변경 요청을 차단합니다. Google 시트 전체를 잠그는 기능은 아닙니다.
응답이 끊기면 성공 여부를 확인할 수 없을 수 있습니다. **이전 전송 결과 확인**을 사용하세요. 확인되지 않은 전송이 있으면 새 전송을 막습니다.
서버 처리 시간을 기다린 뒤에도 예정 탭이 없으면 새 미리보기를 만들 수 있습니다. 이미 생성된 탭의 값이 달라졌다면 공동 편집 여부를 먼저 확인하세요。
Ctrl+Z는 이미 보낸 Google 시트를 되돌리지 않습니다.

## 별도로 학습한 인식 모델

아래는 실험 당시의 이력입니다. 당시의 ‘앱 연결 전’ 문구는 해당 실험 시점의 상태이며, 현재는 기존 인식 어댑터에 모델 3개를 연결한 상태입니다. 현재 릴리스 검증 결과는 진행 요약을 기준으로 합니다.

**최신 모델 개선 (2026-10-26):** 판넬 위치 모델의 입력을 320→448로 높이고 크기·위치·명암 학습을 보강했습니다.
성별·사이즈 분류기와 점수 기준은 유지했습니다. 기존 검증 사진 924벌에서 두 분류 동시 정답은 **923→924벌**, 2950번 위치 점수는 **46.8→94.3%**로 개선됐습니다.
변형 입력 8,316개에서는 위치 검출 보류가 24→1개로 줄었습니다. 같은 32장 CPU 비교의 전체 평균은 0.322→0.330초/벌입니다.
박스는 평균 약 5.5% 넓어지고 평균 IoU는 0.896→0.859로 낮아지는 차이가 있습니다. 같은 촬영 묶음의 회귀 검증이며 새 촬영일 성능 보장은 아닙니다.

## 개발과 검증

기존 가상환경의 고정 버전을 사용합니다. 시스템 전역 설정·패키지를 바꿀 필요가 없습니다.
아래 명령은 기존 개발 PC 환경 기준입니다. 새로 clone한 저장소에는 가상환경·모델·NSIS·기존 빌드가 없습니다. 특히 AI 실행과 설치 빌드에는 별도로 준비한 CPU용 PyTorch 2.11.0/torchvision 0.26.0과 `resources/ai/`의 모델 3개가 필요합니다. `requirements-ab.txt`는 CUDA 실험용이므로 CPU 설치 빌드에 사용하지 않습니다. 재구성 시 필요한 파일과 제한은 [공개 저장소 안내](docs/PUBLIC_REPOSITORY.md)를 확인하세요.

```powershell
.\.venv\Scripts\python.exe -m coatdesk_v2
.\.venv\Scripts\python.exe -m coatdesk_v2 --data-dir .local\v2-dev --software-rendering
.\scripts\test.ps1
.\.venv\Scripts\python.exe scripts\build_v2.py --makensis .downloads\nsis-3.13\nsis-3.13\makensis.exe
```

NSIS는 빌드 PC에서만 필요합니다. 공식 ZIP을 프로젝트 안에 풀어 사용하며 대상 PC에 따로 설치하지 않습니다.
빌드는 기존 릴리스와 다른 `dist-releases/v2-*` 경로에 생성하고 `latest-v2.txt`를 갱신합니다. 기존 프로그램의 `latest.txt`는 유지합니다.
`--oauth-client <관리자 Desktop 연결 JSON>`을 빌드 명령에 추가하면 배포용 연결 설정을 포함합니다.
인증 정보와 토큰을 저장소·로그에 올리지 마세요. 이 저장소에는 배포용 연결 JSON을 포함하지 않습니다.

읽기 전용 실제 사진 검증:

```powershell
.\.venv\Scripts\python.exe scripts\verify_v2.py <사진폴더> <원본 밖 새 검증폴더> --start 1 --end 600 --errors "212,300" --ocr
```

이 명령은 검사·CPU OCR·결과 복원·캐시 키·원본 해시 불변을 검사합니다. 정답 사진을 대조하는 인식 정확도 평가는 아닙니다.
현재 검증 상태와 실환경 제한은 [PROJECT_STATUS.md](PROJECT_STATUS.md)를 확인하세요.
기존 Qt Widgets/JSON 프로그램은 그대로 유지하며 `실행.cmd`로 실행할 수 있습니다. 기존 설명은 [이전 사용법](docs/LEGACY_README.md)에 보존했습니다.
