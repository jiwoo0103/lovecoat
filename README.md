## 실행과 설치

- 개발 폴더에서는 `실행2.cmd`가 `dist-releases/latest-v2.txt`에 기록된 최신 빌드를 실행합니다.
- 다른 PC에는 빌드 폴더의 `CoatDesk-2.4.1-Setup.exe`를 전달해 설치합니다. Windows 10/11 64비트용이며 Python·Excel·GPU를 따로 설치할 필요가 없습니다. CPU 실행 환경과 학습 모델 4개를 함께 포함합니다. 다른 PC 실물 검증은 별도입니다.
- 시작 메뉴의 **외투 작업실 2**로 실행합니다. 화면 표시 문제가 있으면 같은 메뉴의 **호환 모드**를 사용합니다.
- 프로그램을 종료하고 새 설치파일을 실행하면 업데이트됩니다. 제거·업데이트는 작업 기록과 원본 사진을 삭제하지 않습니다.
- 바탕화면 바로가기는 설치할 때 선택합니다. 앱 실행이 바탕화면 작업 폴더나 exe 복사본을 만들지 않습니다.

프로그램 기본 위치는 `%LOCALAPPDATA%\Programs\CoatDesk`, 작업 DB·설정은 `%LOCALAPPDATA%\CoatDesk\v2`입니다.
사진은 원래 폴더에서 읽으며 DB에 사진 파일을 넣지 않습니다. 첫 버전은 같은 PC에서 이어서 작업하는 용도입니다.

엑셀 저장과 사진 분석은 인터넷·Google 계정 없이 동작합니다. Google 연결 JSON이나 로그인 토큰은 새 설치물에 포함하지 않습니다. 기존 로컬 작업 DB와 이전 버전의 인증 파일은 자동 삭제하지 않습니다.

## 작업공간 만들기

1. 홈의 **+ 새 작업** 카드를 눌러 이름과 촬영일을 입력합니다. 이름을 `20261024`처럼 입력하면 촬영일을 제안합니다. 기존 작업 카드나 하단 탭으로 작업을 전환합니다.
2. `0_0001`, `0_0002` 같은 폴더가 들어 있는 사진 상위 폴더를 선택합니다.
3. 사용할 시작·끝 번호와 에러번호를 입력합니다. 예를 들어 1~400번, 에러 212·300이면 실제 폴더가 모두 있을 때 398벌을 사용합니다.
4. **사진 검사하고 만들기**를 누릅니다. 사진 누락·손상을 표시하며 없는 번호를 만들어 넣지 않습니다.

폴더 구조는 `0_0001/img_0_0_0.jpg`, `img_0_0_1.jpg`, `img_0_0_2.jpg` 형식입니다. JPG/JPEG/PNG/WebP/BMP를 지원합니다.
외투코드의 앞자리 0을 유지하며 원본 파일을 복사·이동·이름 변경하지 않습니다.
작업 중에는 메뉴의 **사진 범위 / 에러번호 / 폴더**에서 시작·끝 번호와 에러번호를 함께 바꿀 수 있습니다. 범위를 줄여도 기존 입력·검수·AI 결과는 보관되고, 다시 늘리면 이어서 표시합니다. 새 범위의 사진을 검사하며 신규 옷만 추가합니다. 범위 밖 에러번호는 함께 수정해야 저장됩니다. 옮긴 사진 폴더를 다시 연결하는 기능도 유지합니다.
범위 밖의 에러번호는 안내하며 다른 날짜 작업공간이나 이미 전송한 시트를 자동으로 수정하지 않습니다.

2.4.1에서는 선택 목록의 현재 값을 파란 배경·흰 글씨로 표시하고, 일반·호버 항목은 진한 글씨로 구분합니다.

## 검수와 입력

- 기본은 사진+입력의 2×2 화면입니다. 상단 **배치** 격자에서 1~4행·1~4열을 선택합니다. 4×4도 스크롤 없이 카드를 축소하며, 선택 목록과 확대창은 정상 크기로 표시합니다. 사진만 보기의 배치는 별도로 기억합니다.
- 사진 클릭: 한 벌 선택. Ctrl+클릭: 선택 추가·해제. Shift+클릭: 연속 선택.
- 카드에서 카테고리·성별·성인/유아동·사이즈를 입력하거나 **일괄 입력**으로 선택한 여러 벌에 적용합니다.
- 사이즈는 `2XS, XS, S, M, L, XL, 2XL, 3XL`만 선택합니다. 이전 작업의 목록 밖 값은 보존하고 다시 선택하도록 표시하며 엑셀 저장을 차단합니다. **빠른 입력**을 켜면 모든 항목을 펼친 버튼으로 한 번 클릭해 수정합니다.
- 낮은 점수의 값과 아동 성별에만 필수 확인을 요구합니다. 해당 카드의 **확인** 버튼으로 여러 확인 대상 항목을 한 번에 처리합니다. 값을 수정한 것만으로 필수 검수가 끝나지 않으며, 확인한 대상 값을 다시 바꾸면 재확인이 필요합니다.
- 기준을 충족한 일반 항목은 별도 확인 없이 필수 값이 완성되면 저장할 수 있습니다. 카테고리는 AI 분류 결과를 입력하며 직접 수정할 수 있습니다. 이전 ‘자켓’ 임시 기본값은 AI 결과로 갱신하고 사람이 선택한 값은 유지합니다. **실행 취소 / Ctrl+Z**는 입력과 검수 상태를 함께 되돌립니다.
- 옷 번호 검색과 **분류**의 성별·사이즈·성인/아동 조건은 AND로 적용됩니다. **확인 필요**를 켜면 처리할 항목을 좁힐 수 있습니다.
- 입력과 검수 상태는 SQLite에 자동 저장됩니다. 재실행 시 홈에서 시작하며 열려 있던 작업 탭과 작업별 보기·현재 옷·선택 상태를 복원합니다. 저장 실패 메시지가 나오면 저장 위치를 확인하세요.

## 사진 전용 보기와 인식

상단 **사진+입력 / 사진만 보기**로 전환합니다. 사진만 보기는 정면 기본이며 보기 설정에서 한 벌당 3장 묶음·사진 확대를 조절합니다. 배치 한 칸은 항상 옷 한 벌입니다.
사진 더블클릭 또는 **상세 / 다른 각도**에서 확대합니다. 휠로 확대·축소하고 확대 중 드래그로 이동합니다.
옷을 선택하지 않아도 좌우 방향키로 페이지를 연속 이동합니다. 선택창을 닫거나 값을 수정한 뒤에도 바로 이동합니다. 열린 팝업·텍스트 편집·확대창은 자신의 키 조작을 우선하며 배경 페이지는 움직이지 않습니다. 하단 고정 홈 버튼과 작업 탭으로 이동합니다.

1. **분석**을 누릅니다. AI가 정면 사진에서 판넬 전체를 찾고, 판넬 사진으로 남성/여성/아동과 사이즈를 각각 분석합니다. 현재 페이지부터 분석하며 완료된 옷부터 확인할 수 있습니다.
2. **AI 보류 기준**에서 판넬·성별·사이즈 기준을 바꿀 수 있습니다. 기본값은 각각 **90%·90%·90%**입니다. 첫 2.4 실행에서 이전 저장 기준도 한 번 90%로 맞추며 이후 사용자 변경은 유지합니다. 같은 창의 **옷 소매 (%)**에서 소매 기준도 1~100%로 조절하며 기본값은 90%입니다. 저장된 카테고리 점수의 확인 상태도 새 기준으로 갱신합니다. 기장 기준은 90%입니다. 점수는 모델의 판단 강도이며 실제 정답률이 아닙니다.
3. 후보가 있으면 기준 미달이어도 입력란의 빈 항목에 바로 입력하며 노란색 등으로 확인 필요를 표시합니다. 기존 값은 재분석에서도 덮어쓰지 않습니다. 후보 영역조차 없으면 임의 값을 넣지 않습니다. **머리 확대**나 **머리 영역 지정**으로 확인·재분석할 수 있습니다.
4. 아동 성별은 비어 있으면 남아(남성)로 입력하고 반드시 확인합니다. 여아면 여성으로 바꾼 뒤 확인합니다. 정상 항목에는 별도 제안 적용이나 확인 버튼이 필요하지 않습니다.
5. 전체 정면 사진으로 소매·기장을 분석해 자켓/코트/조끼를 입력합니다. 긴 민소매 또는 설정한 소매 기준(기본 90%)·기장 90% 미달은 ‘기타 + 확인 필요’입니다. 원래 후보·두 점수·사유를 확인할 수 있습니다. 실패하면 임의 분류를 넣지 않으며 기존 판넬 분석 결과는 보존합니다. 이전 임시 자켓은 새 결과로 갱신하되 수동·출처 불명의 과거 값은 유지합니다.

**분석 중단**은 현재 한 벌의 처리를 마친 후 멈추고 결과를 보존합니다. 원본·영역·보류 기준·모델이 같은 완료 결과는 이어서 분석할 때 재사용합니다.
**다시 분석**은 완료 결과도 다시 계산합니다. 재분석 역시 사람의 입력을 덮어쓰지 않습니다.
이 버전은 판넬 위치 1개·판넬 입력 분류 2개·소매/기장 카테고리 1개, 총 4개 모델을 CPU로 실행합니다. 아동 숫자는 확보한 엑셀 대응표로 사이즈를 바꾸며, 아동 성별은 사용자 지시에 따라 모두 남아로 임시 지정합니다. 아동 남녀를 따로 학습한 모델은 아닙니다.
후보를 얻지 못한 항목은 비워 두며 실패를 카테고리 ‘기타’로 바꾸지 않습니다. 점수와 경계 표시는 확정 정답이나 정확도 보장이 아닙니다.

## 엑셀 파일에 날짜별 시트 저장

1. 작업공간 메뉴에서 **엑셀로 저장**을 엽니다.
2. **새 파일**로 저장 위치를 정하거나 **기존 파일**에서 이전에 저장한 `.xlsx`를 고릅니다. 경로를 직접 입력할 수도 있습니다.
3. 촬영일에 따른 시트 이름을 확인하고 미리보기를 만듭니다. 예를 들어 같은 `외투목록.xlsx`에 `20261002`, `20261003` 시트를 추가할 수 있습니다. 같은 이름이 있으면 `(2)`, `(3)`을 붙이며 기존 시트는 덮어쓰지 않습니다.
4. 대상·에러번호로 제외한 수량과 입력 내용을 확인한 뒤 저장합니다. 번호 폴더가 없는 수량은 표시하지 않습니다. 대신 현재 범위에서 불러올 수 있는 사진이 한 장도 없는 **사진 없는 폴더 N개**와 해당 번호를 표시하며, 0개일 때도 표시합니다. 필수 입력이나 필요한 검수가 남아 있으면 저장을 막습니다.

내장 양식에는 헤더·서식·수식·보조목록·드롭다운·열 너비가 포함됩니다. B열 번호는 1부터 연속, C열 외투코드는 `0001`처럼 앞자리 0을 유지합니다. D열은 사진 식별자를 만드는 수식이며 실제 사진을 삽입하거나 업로드하지 않습니다. E/G/H/I 업무 값과 D/K:N 수식을 적용하며 F/J는 비웁니다.

저장은 임시 파일에 만든 뒤 재조회 검증을 거쳐 교체합니다. 미리보기 뒤 작업이나 대상 파일이 바뀌면 다시 미리보기를 만들어야 합니다. 다른 프로그램에서 파일을 열어 잠근 경우 Excel을 닫고 재시도하세요. 서명·구조 보호 등 지원하지 않는 파일은 안내하고 저장을 차단합니다.
기존 파일의 시트·차트·외부 링크 자료는 보존하며, 새 시트의 서식만 추가합니다. Ctrl+Z는 이미 저장한 엑셀 파일을 되돌리지 않습니다.

Google 시트에서 사용하려면 사용자가 **파일 → 가져오기 → 엑셀 선택 → 새 시트 삽입**으로 가져올 수 있습니다. 앱의 Google 연결은 필요하지 않으며 가져온 파일과 원본 엑셀은 자동 동기화되지 않습니다. Google 변환 후 서식·수식 확인은 별도입니다.

## 별도로 학습한 인식 모델

아래는 실험 당시의 이력입니다. 당시의 ‘앱 연결 전’ 문구는 해당 실험 시점의 상태이며, 현재는 기존 인식 어댑터에 모델 3개를 연결한 상태입니다. 현재 릴리스 검증 결과는 진행 요약을 기준으로 합니다.

**최신 모델 개선 (2026-10-26):** 판넬 위치 모델의 입력을 320→448로 높이고 크기·위치·명암 학습을 보강했습니다.
성별·사이즈 분류기와 점수 기준은 유지했습니다. 기존 검증 사진 924벌에서 두 분류 동시 정답은 **923→924벌**, 2950번 위치 점수는 **46.8→94.3%**로 개선됐습니다.

## 개발과 검증

기존 가상환경의 고정 버전을 사용합니다. 시스템 전역 설정·패키지를 바꿀 필요가 없습니다.
아래 명령은 기존 개발 PC 환경 기준입니다. 새로 clone한 저장소에는 가상환경·모델·NSIS·기존 빌드가 없습니다. 특히 AI 실행과 설치 빌드에는 별도로 준비한 CPU용 PyTorch 2.11.0/torchvision 0.26.0과 `resources/ai/`의 모델 4개·카테고리 참조 자산이 필요합니다. `scripts/prepare_category_runtime.py`로 고정된 실험 모델과 참조 디렉터리에서 실행 자산을 준비합니다. `requirements-ab.txt`는 CUDA 실험용이므로 CPU 설치 빌드에 사용하지 않습니다. 재구성 시 필요한 파일과 제한은 [공개 저장소 안내](docs/PUBLIC_REPOSITORY.md)를 확인하세요.

```powershell
.\.venv\Scripts\python.exe -m coatdesk_v2
.\.venv\Scripts\python.exe -m coatdesk_v2 --data-dir .local\v2-dev --software-rendering
.\scripts\test.ps1
.\.venv\Scripts\python.exe scripts\build_v2.py --makensis .downloads\nsis-3.13\nsis-3.13\makensis.exe
```

NSIS는 빌드 PC에서만 필요합니다. 공식 ZIP을 프로젝트 안에 풀어 사용하며 대상 PC에 따로 설치하지 않습니다.
빌드는 기존 릴리스와 다른 `dist-releases/v2-*` 경로에 생성하고 `latest-v2.txt`를 갱신합니다. 기존 프로그램의 `latest.txt`는 유지합니다.
새 빌드는 Google 인증 모듈·연결 JSON·사용자 토큰을 포함하지 않습니다. 이전 로컬 인증 자료도 저장소·로그에 올리지 마세요.

카테고리 학습 도구의 손실함수 테스트 등 PyTorch를 사용하는 검증은 CPU PyTorch/torchvision을 준비한 환경에서 실행합니다. 현재 개발 PC는 `.local/ai-installer-venv/Scripts/python.exe -m pytest tests/test_category_expanded_model.py`로 확인했으며 기본 `.venv`에는 PyTorch가 없습니다. 원형 Qt Widgets 앱의 Google 테스트는 현재 V2의 최소 의존성과 별도인 이전 Google 개발 의존성이 필요합니다.

읽기 전용 실제 사진 검증:

```powershell
.\.venv\Scripts\python.exe scripts\verify_v2.py <사진폴더> <원본 밖 새 검증폴더> --start 1 --end 600 --errors "212,300" --ocr
```

이 명령은 검사·CPU OCR·결과 복원·캐시 키·원본 해시 불변을 검사합니다. 정답 사진을 대조하는 인식 정확도 평가는 아닙니다.
현재 검증 상태와 실환경 제한은 [PROJECT_STATUS.md](PROJECT_STATUS.md)를 확인하세요.
기존 Qt Widgets/JSON 프로그램은 그대로 유지하며 `실행.cmd`로 실행할 수 있습니다. 기존 설명은 [이전 사용법](docs/LEGACY_README.md)에 보존했습니다.
